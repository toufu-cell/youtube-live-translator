# 開発環境での確認

2026-09-29、macOS上のChrome for Testing 153.0.8010.12で確認しました。
対象Windows機の受入結果ではありません。

## モデルの実行と通信

ビルドした拡張内のWorkerで、固定revisionのWhisperとNLLBを読み込みました。
公開の評価用音声の先頭4秒を入力し、英語認識と日本語出力を確認しました。
音声は16kHzのFloat32です。

| 項目 | 結果 |
| --- | --- |
| モデル準備 | 約66.4秒。一部の取得済みCacheがある状態 |
| 認識と翻訳 | 約4.1秒。音声の収集時間と字幕表示時間を含まない |
| 翻訳品質 | 短い入力でも訳抜けがあり、品質合格とは判定していない |
| 準備中の通信 | Hugging Faceとモデル配信CDNへのGET |
| 推論中の通信 | 観測した要求なし |

この測定では、推論だけで3秒を超えています。
実際の字幕遅延や、対象Windows機での性能を示す値ではありません。
発表イベントの代表区間による品質比較とモデル選定は、Windowsでの受入確認に残っています。

`scripts/browser-model-check.mjs`でモデルの読込みと推論を再確認できます。
Playwright、Chromiumの実行ファイル、16kHzのFloat32音声を用意します。
場所は`YTL_PLAYWRIGHT`、`YTL_CHROME`、`YTL_AUDIO`で指定できます。
モデルは検証用の一時プロファイルへ取得されます。
実行後は、そのプロファイルを削除します。

## 音声取得の継続と停止

ブラウザー内の試験用ページで音を再生し、拡張の呼出し後に実際の`chrome.tabCapture`を開始しました。
取得状態は`active`になり、ポップアップを閉じた後も維持されました。
別ページへ移動すると、取得状態は`stopped`、拡張の状態は`idle`になりました。

モデル準備後、公開の評価用音声を試験用ページの動画要素から再生しました。
実際のタブ音声取得、英語認識、日本語翻訳、動画上への字幕表示まで通りました。
その間の外部通信は観測されず、停止操作後に取得状態が`stopped`になることも確認しました。

最新版を新しいプロファイルで実行した際の初回表示は、先頭PCM到着から約5.1秒でした。
内訳は音声収集約1.5秒、推論約3.5秒、表示までの転送約0.02秒です。
これは試験用音声の1回の初回表示であり、意味の正しさを含む速度評価や中央値・p95ではありません。
幅800pxから340pxへの変更と、文字サイズ36pxへの変更後も最大2行になることを確認しました。

ビルド後の試験には、拡張機能の再読み込みが必要です。
同じ検証用プロファイルを再利用したところ、以前のservice workerが残りました。
再読み込み後に、ポップアップから計測値を取得できることを確認しました。

この試験はYouTubeのURLに応答する試験用ページを使用しています。
YouTubeの実ライブ、広告、本編復帰、イベント全体の連続視聴は[Windows受入手順](windows-acceptance.md)で確認します。

## 修正後の表示とYouTube録画

長い字幕の表示中に同じ区間の更新を送り、即時に改訂版へ置き換わることを確認しました。
新しい区間は次のページ切替で表示され、未表示部分の省略通知が出ました。
表示直後から約1.75秒の時点で、新しい区間の字幕と省略通知を確認しています。

実際の[Apple WWDC25の録画](https://www.youtube.com/live/0_DjDdfqtUE)でも、冒頭を短時間再生しました。
`/live/`形式のURLから、開始、一時停止、再開、字幕表示、停止まで通りました。
一時停止と再開の際はモデル準備状態へ戻らず、停止後の音声取得状態は`stopped`でした。
録画での操作確認であり、実ライブ・広告・翻訳品質・イベント全体の受入結果ではありません。
